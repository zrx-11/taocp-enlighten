# 模式与框架库

## 框架：判断一个排序该用什么

1. **数据在哪**：内存 → 内部排序；磁盘 → 外部排序。
2. **要不要稳定**：要 → 合并排序或基数排序；不要 → 快排、堆排。
3. **最坏要不要保证**：要 → 堆排序；不要 → 快排。
4. **数据有无现成结构**：近乎有序 → 插入排序；键值范围小 → 基数排序；链表 → 合并排序。

## 框架：判断一个查找该用什么

1. **能不能随机访问**：不能 → 顺序查找或跳表。
2. **数据动不动**：静态 → 有序数组加二分；动态 → 平衡树。
3. **数据在不在内存**：在磁盘 → B 树。
4. **要不要范围查询**：要 → 树；只要精确匹配 → 散列。

## 决策规则：散列的装载因子

- α < 0.5：开放地址法还很轻松。
- 0.5 ≤ α < 0.75：可用，但探测长度明显上升。
- α ≥ 0.75：必须扩容重散列，否则退化。
- 链地址法可容忍 α > 1，但缓存不友好。

## 反模式

- **对已排序数据取首元素当快排基准**：必然 O(n²)。
- **用 2 的幂当散列表长度**：只取键的低位，低位有规律就冲突。
- **开放地址法直接清空槽**：截断探测链，后续查找失败。
- **用比较排序去排键值范围很小的整数**：明明可以用基数排序到线性。
