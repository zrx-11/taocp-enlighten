# 模式与框架库

## 框架：算法分析四步

1. **定基本操作**：选一个在循环里反复出现、能代表代价的动作（比较、求余、赋值）。
2. **定输入规模**：写清 n 是什么，取值范围是什么。平均值必须连同取值范围一起说。
3. **写代价函数**：数出该操作在每类输入上的执行次数，得到 T(n)。
4. **化简与比较**：化成渐近形式，只留最高次项；再对不同算法在同一 n 上比较。

## 决策规则：线性结构怎么选

- 只在末端进出，后进先出 → 栈，用数组加一个 TOP 指针即可。
- 两端分工，先进先出 → 队列，注意用循环数组避免“假溢出”。
- 中间频繁插入删除 → 链表，代价是每个节点多一个链字段、访问要顺着走。
- 需要 O(1) 找到前驱 → 双链表；只需要首尾相接 → 循环链表。
- 二维表极稀疏 → 正交表（行、列、值三元组），不要开满二维数组。

## 决策规则：存储管理怎么选

- 块大小固定、要求快 → 伙伴系统，切分与合并都只跟二进制位打交道。
- 块大小差异大、要省空间 → 首次适配加边界标记，回收时与相邻空闲块合并。
- 存在大量共享节点、无法判断何时可删 → 标记-清扫，先标出可达节点再整体回收。

## 反模式

- **用“显然会停”代替终止性证明**。正确做法是指出一个随每轮严格减小、又有下界的量（欧几里得算法里就是余数 r）。
- **把平均值当成与范围无关的常数**。换一个取值范围，平均值就变了。
- **在链表上做按下标访问**。链表没有随机访问能力，按下标访问是 O(n)，要频繁按下标取就换数组。
- **给每个节点都开满链字段**。多链结构应按实际关系开链，稀疏矩阵更是要用正交表。
